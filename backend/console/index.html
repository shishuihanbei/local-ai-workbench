自定义 OpenAI 兼容怎么接

        

          这张卡不安装软件，只测试地址是否连通
          
        

      

      

        

          一句话说明：先在电脑或服务器上准备一个兼容 /v1/models 和 /v1/chat/completions 的服务，再回工作台填地址、测试、保存，最后到「供应商」和「路由」两页完成接入。工作台不会替你安装这个服务，平台卡上的按钮叫“测试连接”，不会下载任何东西。
        


        

          

            它到底是什么
            
一个通用入口：只要对方提供 OpenAI 格式的模型列表和聊天接口，就能接进来，不限制是 Ollama、LM Studio、vLLM 还是第三方 API。

          

          

            和「供应商」页的区别
            
部署页这张卡只检查地址通不通；真正保存 Key、模型名并让聊天走它，要去「供应商」页新建供应商。

          

          

            什么服务能接
            
判断标准只有两条：GET /v1/models 能返回模型列表；POST /v1/chat/completions 能正常聊天。

          

        


        

          
照着做：六步接入

          
    
            
  1. 先启动外部服务。本机装 Ollama、LM Studio、vLLM，或者直接买第三方 API。没启动服务，工作台这边填什么地址都不会通。
    2. 
            
  2. 在部署页填“服务地址”并测试。找到“自定义 OpenAI 兼容”卡片，地址填服务根地址，例如 Ollama 填 http://127.0.0.1:11434，点“测试连接”。成功时会显示“连接正常 · N 个模型”。
    3. 
            
  3. 点“保存选择”。测试通过不等于保存；不点保存，刷新页面后地址会回到默认值。
    4. 
            
  4. 去「供应商」页建供应商。预设选“自定义 / 其他 OpenAI 兼容接口”，Base URL 要带 /v1，例如 http://127.0.0.1:11434/v1；本机服务 Key 可留空；模型名必须和 /v1/models 返回的一模一样。
    5. 
            
  5. 去「路由」页绑定。新建策略，供应商选刚才建的，点“自动匹配”或手动把工作台模型映射到对方的模型名。只加供应商不建路由，网页聊天不一定会走它。
    6. 
            
  6. 回前端实测。选对应模型发一句“你好”；能正常回复就说明整条链路通了。普通用户还要在「用户」页把模型分配给他。
    7. 
          

        


        

          最容易填错的地方：部署页填“根地址”（一般不带 /v1），供应商页填“Base URL”（一般必须带 /v1）。因为供应商页会在后面自动拼 /models 和 /chat/completions，少一段就会 404。

现象最常见原因怎么处理

              
                
测试显示“未连接：ConnectError”服务没启动、端口填错，或只监听了 127.0.0.1先在本机浏览器打开 /v1/models；远程访问要让服务监听 0.0.0.0 并放行防火墙端口

                
HTTP 404路径少了或多了 /v1部署页填根地址；供应商页 Base URL 带 /v1；用浏览器直接访问 /v1/models 验证

                
HTTP 401 / 403Key 没填、填错、额度用完，或该服务要求额外请求头重新复制 Key，不要带 Bearer；到服务商控制台确认 Key 状态

                
连接正常，但模型列表是 0 个服务启动了但没加载模型先在服务里加载/拉取模型；Ollama 用 ollama list 确认模型存在

                
聊天时报“model not found”模型名和工作台里填的不一致以 /v1/models 返回的 id 为准，大小写和斜杠都要一致

                
供应商测试通过，网页聊天还是走本地只加了供应商，没建路由或没分配模型到「路由」页建云端策略；普通用户还要在「用户」页分配模型
