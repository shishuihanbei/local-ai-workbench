# 模型接入

工作台不内置模型，只负责会话、检索、调度和界面。模型可以跑在本机，也可以跑在局域网另一台机器上。

## 选择方式

| 方式 | 适合 | 工作台里的入口 |
| --- | --- | --- |
| llama.cpp | 想由工作台托管 GGUF、可控参数 | 控制台「部署」→ llama.cpp |
| Ollama | 最省事，跨平台 | 控制台「供应商」→ Ollama 预设 |
| LM Studio | 桌面图形化管理 | 控制台「供应商」→ LM Studio 预设 |
| vLLM | Linux + NVIDIA，追求吞吐 | 控制台「供应商」→ vLLM 预设 |
| 自定义 OpenAI 兼容 | 任意第三方或自建服务 | 控制台「供应商」→ 自定义 |

## Ollama（推荐给新手）

```bash
ollama pull qwen2.5:7b
ollama serve
```

默认监听 `127.0.0.1:11434`。控制台新建供应商：

- Base URL：`http://127.0.0.1:11434/v1`
- API Key：留空
- 模型名：`qwen2.5:7b`

验证：

```bash
curl http://127.0.0.1:11434/v1/models
```

能返回 JSON 就说明接口就绪。

## LM Studio

1. 下载模型。
2. 打开 **Developer** 页，点 **Start Server**。
3. 默认端口 `1234`。
4. 供应商 Base URL 填 `http://127.0.0.1:1234/v1`，Key 留空。

## vLLM

适合 Linux + NVIDIA：

```bash
vllm serve Qwen/Qwen2.5-7B-Instruct \
  --host 0.0.0.0 \
  --port 8000
```

供应商 Base URL：`http://服务器IP:8000/v1`。

## llama.cpp（工作台托管）

控制台「部署」页可以：

1. 检测本机硬件和 llama.cpp。
2. 从 GitHub 多线路下载安装包；国内网络会自动走加速镜像。
3. 扫描模型目录。
4. 启动/停止 `llama-server`，设置上下文、线程、GPU 层数。

模型目录默认 `./models`，也可以指向 NAS 挂载目录。常见量化：

- `Q4_K_M`：体积和质量的平衡，最常用。
- `Q5_K_M`：质量更好，显存/内存要求更高。
- `Q8_0`：接近原始精度，适合大内存。

## 自定义 OpenAI 兼容

需要两件事：

1. 服务根地址（不带 `/v1`），例如 `http://192.168.1.20:8001`。
2. 模型 ID，必须和 `/v1/models` 返回的 `id` 完全一致。

供应商页填 Base URL 时带上 `/v1`。远程服务要监听 `0.0.0.0` 并放行防火墙端口。

## 多机算力池

如果有多台机器：

1. 控制台「算力」页登记节点，填机器名和 `http://IP:端口/v1`。
2. 建一个池，把节点加进去。
3. 池会得到一个统一模型名。
4. 客户端仍然只连工作台的 `9100`，模型名填池名。

节点掉线时池会自动跳过；恢复后重新参与。

## 常见错误

| 错误 | 原因 | 处理 |
| --- | --- | --- |
| `ConnectError` | 服务没启动 / 端口错 / 只监听 127.0.0.1 | 先在本机浏览器打开 `/v1/models` |
| `401` | API Key 错 | 重新填供应商 Key |
| `404 model not found` | 模型名不一致 | 用 `/v1/models` 返回的 `id` |
| 回答很慢 | 模型太大 / 没开 GPU / 上下文太长 | 换小量化、加 GPU 层、降 `ctx` |
| 中文乱码 | 终端编码 | 设置 `PYTHONUTF8=1`，用 UTF-8 保存文件 |
