# 安全部署

这是一个**本机/内网**工具。默认配置适合个人电脑和可信局域网，不适合直接暴露到公网。

## 上线前检查

- [ ] 管理员使用独立强密码，不和别的网站共用。
- [ ] 关闭自助注册，或只允许指定邮箱/域名。
- [ ] 修改默认端口只减少扫描，不是安全措施。
- [ ] 用 Nginx / Caddy / NAS 反代做 HTTPS，不要裸 HTTP 上公网。
- [ ] 防火墙只放行反代端口，不直接放行 9100。
- [ ] 备份 `data/`，并单独保管 `data/secret.key`。
- [ ] 检查 `data/config.json` 没有把内部地址、测试 Key 写进去。
- [ ] 如果开了长期记忆、知识库、总资料库，明确告知使用者数据范围。
- [ ] 定期看调用日志和内容安全命中记录。

## 认证与会话

- 密码用 scrypt 加盐哈希，不存明文。
- 会话 Cookie 为 HttpOnly；写操作校验 CSRF。
- 登录失败有限流，防止暴力猜解。
- 首次启动没有默认账号，必须在本机初始化管理员。
- 可关闭注册；管理员可在控制台停用账号、重置密码、调整角色。

## 密钥

供应商 API Key 使用 AES-256-GCM 加密，主密钥来自：

1. 环境变量 `WORKBENCH_SECRET`，或
2. `data/secret.key` 自动生成。

加密格式带 `enc:v1:` 前缀，旧明文会在启动时迁移。

> 丢失主密钥后，已保存的供应商 Key 无法恢复。请把 `secret.key` 和数据库一起备份，但不要提交到 Git。

## 网络暴露

推荐拓扑：

```text
公网 → 域名 + HTTPS → 反向代理 → 127.0.0.1:9100
```

不推荐：

```text
公网 → 直接 9100
```

最低要求：

- 反代开启 TLS 1.2+。
- 上传大小限制在合理范围。
- 关闭不必要的 HTTP 方法。
- 只允许自己的 IP 段访问管理控制台，或用 VPN。
- 不要把 `data/` 目录暴露成静态站点。

## 内容与数据

- 对话、附件、生成文件都写本机，不会自动发到第三方。
- 联网检索时，只把检索词发给搜索引擎；不要把整段私密对话发出去。
- 内容安全默认本地规则；如果开启模型复核，复核请求会发给所配置的模型服务。
- 长期记忆默认关闭，开启后按账号隔离。
- 总资料库由管理员维护，普通用户只能读授权范围。

## 备份与恢复

备份：

```bash
tar czf workbench-backup-$(date +%Y%m%d).tar.gz data/
```

恢复：

1. 停服务。
2. 解压覆盖 `data/`。
3. 启动，等待迁移。
4. 用管理员登录验证。

注意：

- 不要只备份 `workbench.db` 而漏掉 `secret.key`。
- 备份文件里可能有真实对话和上传文件，按敏感数据保管。
- 恢复前先复制一份当前 `data/`，避免覆盖后无法回退。

## 漏洞与依赖

- 依赖版本固定在 `requirements.txt`，升级前跑测试。
- 不在仓库里放 `.env`、数据库、密钥、模型。
- 生产环境关闭调试和 `--reload`。
- 如果发现安全问题，请通过仓库 Issue 私下联系维护者，不要公开利用细节。

## 已知边界

- 单进程 SQLite，不适合高并发公网多租户。
- 内网穿透是便利功能，不等于安全加固；用之前先评估暴露面。
- 模型本身可能产生错误或有害内容，内容安全不能替代人工审核。
- 浏览器端没有做完整的 XSS 沙箱，导入不可信内容前请先审查。
